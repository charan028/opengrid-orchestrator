Data model

All state lives in PostgreSQL, schema og, created by the SQL migrations in orchestrator/migrations/ (0001 to 0050 at r3.4.3; there is no 0015, 0048 or 0049). The migrations create 75 tables plus 2 default partitions (telemetry_default, telemetry_1m_default) and one view (lifecycle_partitions). Daily partitions of telemetry and telemetry_1m are created at run time by the lifecycle job. The "Mig." column gives the migration that created each table; later migrations add columns (for example 0027 and 0034 on telemetry, 0029, 0032, 0036 and 0043 on hub, 0046 on bank and contract, 0047 on as_deployment). The migrations are listed under Migrations added in r3.4 (0041-0043) and Migrations added in r3.4.1 to r3.4.3 (0044-0050). A generated snapshot of the whole schema is kept in orchestrator/schema/og_schema.sql. "Written by" and "Read by" name the Python package and, in brackets, the process it runs in.

Migrations added in r3.4

r3.4 adds three additive migrations on top of r3.3's 0001-0040. No table is created or dropped. Column additions that r3.4 already carried, such as 0027_discharge_flow_telemetry (flow columns on telemetry and hub_state, and the hub.lat/lon backfill), are unchanged.

MigrationChangeWhy
0041_trace_authz_deny.sqlThe og.trace.decision_type CHECK accepts AUTHZ_DENY. Added NOT VALID (no scan of og.trace) and deliberately not validated in the same file.Every audited deny raised a check violation, was journalled as a database outage, and blocked trace-journal replay for the whole process.
0042_drop_hot_indexes.sqlDrops 0039's og.hub_state_last_seen_hub_idx and og.hub_state_p_kw_hub_idx.Both columns change on every telemetry flush, so the indexes defeated HOT updates on the hottest table. The Fleet table sorts by P and telemetry age with a scan and a top-N sort instead.
0043_hub_device_reported.sqlAdds og.hub.device_units, device_rated_kw, device_rated_kwh, device_reserve_floor_pct, device_lat, device_lon.H4: what a battery reports is kept apart from the seed. units, p_kw, e_kwh, r_kwh (the K1 reserve), lat and lon are never written from a device report; a difference raises ALR-DEVICE-RATING-MISMATCH.

og.hub.pv_rated_kw (0029) is still never written by a seed. At r3.4 the guardian reads NULL as [guardian.flow].default_pv_rated_kw = 10 kW per hub (conservative), not 0; an explicit 0 still means no PV.

Migrations added in r3.4.1 to r3.4.3

Five additive migrations follow 0043; there is no 0048 or 0049. Two create tables (dispatch_call, delivery_record), bringing the total to 75 tables. Widened CHECK lists are added NOT VALID (no scan under the exclusive lock) where they are strict supersets; 0044 to 0046 set lock_timeout = 5 s.

MigrationChangeWhy
0044_asset_class_mobile_storage.sqlog.asset.asset_class accepts MOBILE_STORAGE; a MOBILE_STORAGE row must name its bank (asset_mobile_storage_link). Both NOT VALID.D-31 trucks: the guardian rates a hub at nameplate og.hub.p_kw only when it has a SUBSTATION or MOBILE_STORAGE asset row; before 0044 every truck stayed at the 11 kW home cap.
0045_feed_obs_extreme_uncorroborated.sqlog.feed_obs.quality accepts EXTREME_UNCORROBORATED (added NOT VALID, then validated under a lock that does not block ingest).FR-ING-117: an extreme but plausible real-time price is kept and flagged until corroborated, never dropped or clipped.
0046_noie_switch.sqlog.utility.utility_id also LCRA and RAYBURN; og.contract.name, is_sample with two CHECKs; og.bank.availability, availability_reason (REGULATED_NO_CONTRACT), availability_since and index ix_bank_unavailable. No backfill in the migration.D-37: LZ_LCRA and LZ_RAYBN are regulated territory; the "Regulated market – no contract" state is one bank-level availability shared by selector, allocator, guardian, UI and APIs; sample contracts can never be called or billed.
0047_dispatch_calls.sqlog.as_deployment: sources UTILITY, GRID_LINK, ERCOT; requested_kw (CHECK below 0), call_id; index on open deployments per obligation. Creates og.dispatch_call with an idempotency unique index on (principal, idempotency_key).D-33: calls from every origin go through one core path and every attempt, refused ones included, is recorded for the caller to read back.
0050_delivery_record.sqlCreates og.delivery_record and five indexes (window, open records, contract, utility, deployment).D-38: per-call delivery verification (PASS, PARTIAL, FAIL, AT_RISK alerts) from telemetry, written by og-settle's delivery job.

Truck positions and nameplate ratings need no new column: a truck's live position is the device-reported og.hub.device_lat/device_lon from 0043, read with device_info_at as an age limit by both the selector and guardian G-35, and its rating is the seeded nameplate og.hub.p_kw. The 600 kVA transformer sizing (D-36) is data in og.service_transformer, not a migration.
