Control room (/og/)

The Control room is the console's landing screen. It answers one question: what is the fleet doing right now, and has any promise been broken today. Everything below the one-line status sentence is evidence for that sentence. It is read-only apart from alert acknowledgement.

Shared chrome (every console screen)

Every screen extends the same layout (ui/templates/base.html). The elements below behave identically on Fleet, Dispatch, Markets, System Health, Profitability, Billing & audit and Power quality, so they are described once here.

Fleet monitoring & control (/og/fleet)

The Fleet screen is where every hub (home battery, truck, substation BESS) is found, inspected and, by operators, commanded. It holds the fleet table, the fleet map, the hub detail drawer, the grid-charging schedule and the action cards: command one hub, command a selection, scoped safe stop and safe-stop release. Every write is two steps: propose, then confirm the exact summary the API returns.

Manual target and ramp statuses (r3.4.3)

Since r3.4 one status rule (core.manual_targets.effective_targets) is shared by the engine, the API list and the guardian. Per hub, the newest target has exactly one status. Precedence: operator or late-record cancel, then safe stop, then expiry, otherwise ACTIVE. Only ACTIVE targets are ramped, marked in the table or shown in the drawer.

Dispatch & commitments (/og/dispatch)

The Dispatch screen shows what the fleet has promised and how it is keeping those promises: every obligation's journey from offer to verified delivery, ERCOT ancillary-service awards and their deployment, the capacity ledger over time, the optimizer's latest plan, commitment-lock events (K13) and the 2-second grants. Operators can deploy or stop an ERCOT AS award and issue a utility's call on a tolling obligation; everything else is read-only. Since r3.4.1 every discharge call, whatever its origin (this screen, the utility customer API, the DNP3 grid link, the ERCOT AS instruction poller), goes through one core path (opengrid.calls, D-33) with the same checks, and is recorded in og.dispatch_call and og.as_deployment.
