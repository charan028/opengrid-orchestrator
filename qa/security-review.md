# OpenGrid Orchestrator — First-Release Security Review

Read-only build-phase security assessment against the live deployment on `192.168.5.35`
(`base.tocy-net.net`). Approved 2026-09-25 per `BUILD.md`. No product code, server config, or
services were modified; no services were restarted. Scope: command integrity (K3/K6/K8/K10/K12/K13),
secrets handling, network exposure, MQTT broker, API, dependencies, systemd hardening, and
supply-chain/repo hygiene. Per instructions, in-progress work on "selector bank IDs" and "the fleet
sim" (`og-sim-fleet`) is explicitly out of scope and not reported here.

## 1. Executive summary

The safety-critical core — guardian sole-signer, command freshness, safe-stop stop-only asymmetry,
trace-before-sign, clock-quality gating, and the K13 commitment lock — is implemented correctly, with
no bypass path found in the guardian/safestop/hub-verification code. SQL is parameterized throughout,
secrets are wrapped/masked in the feeds and guardian/safestop key code, and no secret values were
found in git history, source, or sampled logs. The most serious finding is operational, not
cryptographic: two of the four integration-simulator processes (`ogsim.control`, the anomaly-injection
control plane, and `ogsim.market`) default to binding `0.0.0.0` instead of loopback and are confirmed
reachable and **unauthenticated** directly over the LAN, completely bypassing Apache's Basic Auth —
the single authentication layer the whole architecture relies on. Secondary findings: leftover
`api_keys.env.bak.*` files under `/etc/opengrid`, a keygen CLI that prints a raw signing seed to
stdout, an open `ogtest/#` MQTT ACL pattern, and the absence of any CSRF mitigation for the
Basic-Auth-fronted HTMX UI.

## 2. Findings

| ID | Severity | Area | Evidence | Risk | Recommendation |
|---|---|---|---|---|---|
| F-01 | **Critical** | Network exposure | Live: `ss -ltnp` shows `0.0.0.0:8091` (og-sim-control, pid 87433) and `0.0.0.0:8090`/`18090` (og-sim-market). | F-05 | Low | Secrets hygiene | `orchestrator/src/opengrid/safestop/keys.py` `_cli()` (~line 127) prints the raw 32-byte signing seed as `seed_hex={seed.hex()}` to stdout on every `keygen` invocation. `opengrid/guardian/keys.py`'s equivalent `keygen()` does **not** print the seed — asymmetric behavior between the two key-generation tools. | A one-time bootstrap command, but stdout is easy to capture inadvertently (shell history via terminal scrollback capture, a CI/deploy log if ever wrapped in automation, `script`/tmux logging). `qa/merge-notes.md` §8 already documents that this file's format bug forced someone to copy the printed hex by hand during the live deploy — i.e. the print statement was actually relied on once already. | Drop the stdout print (the private-key file at `--key-out` is already the durable, permissioned artifact) or gate it behind an explicit `--print-seed` flag with a loud warning, matching guardian's `keygen` behavior. |

| F-07 | Info | TLS config | `base-ssl.conf` sets `SSLEngine on` and cert/key paths only; no explicit `SSLProtocol`/`SSLCipherSuite` override was found in `sites-enabled/` (relies on the distro's global `mods-enabled/ssl.conf` defaults, not reviewed here since it's outside `opengrid.conf`'s scope and the review's read list). | Unverified whether the effective TLS policy (protocol floor, cipher suite) meets the organization's standard. | Confirm `/etc/apache2/mods-available/ssl.conf` (or equivalent) enforces TLS 1.2+ with a modern cipher suite; out of `opengrid.conf`'s ownership so this is an infra-team follow-up, not a deploy-role fix. |

## 3. Verified controls (passed)

**Command integrity (K3/K6/K8/K10/K12/K13):**
- **K3 sole signer** — `opengrid.guardian.service.GuardianService._finalize` is the only code path that calls `sign_payload`; `opengrid.core.crypto.sign_payload`/`verify_payload` are the single shared implementation (guardian signs, `ogsim.common.crypto` verifies). No other component in `orchestrator/src` or `integration-sims/src` calls `sign_payload`.
- **Key custody** — `guardian_ed25519.key`/`safestop_ed25519.key` are mode `600 opengrid:opengrid`; public keys `644`. Seeds are never logged: 0 hits for `signing_seed`/`GUARDIAN_SIGNING_SEED`/`OG_SAFESTOP_SIGNING_SEED`/`seed_hex` across 5,000-line samples of `og-guardian`/`og-safestop` journald output.
- **K6 freshness** — `opengrid.guardian.checks.check_g13_freshness` (epoch/seq/lease, independently re-checked against `og.lease_state`, which now survives a guardian restart per `qa/merge-notes.md` §4/§11) and `ogsim.common.crypto.verify_signature` on the hub/verifier side both gate on signature + freshness before acting.
- **K8 stop authority** — `opengrid.safestop.service.SafestopService.release()` unconditionally raises `ReleaseNotPermittedError`; the stop-only key (`opengrid.safestop.keys`) is structurally distinct from the guardian key and only ever used by `build_engage_event`. Mosquitto ACL confirms the asymmetry on the wire: `og_safestop` may only `write og/v1/stop/#`, never `og/v1/cmd/#`; only `og_guardian` may write `og/v1/cmd/#`/`og/v1/lease/#`. `og-safestop.service`'s unit file has no `Requires=`/`After=`/`BindsTo=` on `og-engine.service`/`og-guardian.service`, confirmed live via `systemctl show`.
- **K10 trace-before-act** — `GuardianService._run_checks` checks `G-14` (`exists_preimage`) before any other check and returns immediately on failure ("nothing downstream is trustworthy without the pre-image"); `SafestopService.engage()`'s docstring and code order trace-append before the `stop_event` insert before the MQTT publish.
- **K12 clock quality** — `evaluate_and_sign` runs `check_g20_clock_quality` first and alone, before any other check, and short-circuits to `TIMEOUT` on failure — matches 02a §6.2a's ordering requirement exactly.
- **K13 commitment lock** — `opengrid.core.limits.check_commitment_lock` enforces `new_kw >= min(frozen_kw, prior_kw)` unless an allowed reason code is present (`R-AS-RELEASE` additionally gated by a config flag, default off); `GuardianService._check_commitment_lock` enumerates *active obligations independently* from the guardian's own read model rather than trusting the batch's item list, so omitting or relabelling an obligation cannot evade G-19.
- **No bypass paths found**: no dev/debug/test-mode branch, alternate signing endpoint, or config toggle was found in `guardian/`, `safestop/`, or `ogsim/common/crypto.py` that skips signing, freshness, trace-ordering, clock-quality, or commitment-lock checks. `orchestrator/config/test.toml` points to distinct `/tmp` test key paths, not a mechanism to skip verification.

**Secrets:** `.gitignore` (both locally and on the server's `/opt/opengrid/src` checkout) covers `*.env`, `secrets*`, `*.key`, `*.pem`. Zero matches for private-key/AWS-style-key/hardcoded-password patterns in a static grep of both `orchestrator/src` and `integration-sims/src` on the server, and zero matches in `git log --all -p` on `/opt/opengrid/src`. `opengrid.feeds.secrets.Secret` wraps every credential immediately after resolution and only unwraps at the one HTTP call site; `mask_secrets` scrubs error text as a backstop. ERCOT client (`feeds/ercot.py`) and its market-simulator counterpart (`ogsim/market/security.py`, `TokenStore`) never log a raw token/subscription key. `/etc/opengrid/secrets.env` and `api_keys.env` are `640 root:opengrid`; `htpasswd` is `640 root:www-data` (matches the documented ACL design). journald sampling (5,000 lines × 10 units) found 1 borderline hit on `og-feeds` (a single log line matching a generic keyword pattern, not a value) and 0 on every other unit.

**Network exposure (besides F-01):** `ss -ltnp` confirms Postgres (`127.0.0.1:5432`), Mosquitto (`127.0.0.1:1883`), and `og-api` (`127.0.0.1:8080`) are loopback-only. Apache is the only externally reachable listener for the intended app surface (`*:443`/`*:80`). `opengrid.conf`'s two `<Location>` blocks both `RequestHeader unset X-Remote-User` before re-asserting it from `%{REMOTE_USER}` (anti-spoofing, confirmed by code review of `api/auth.py`'s matching trust assumption). Live `curl` confirms: no-auth → `401` on both `/og/` and `/ogsim/`; correct-role creds → `200`; wrong-realm creds (`operator` against `/ogsim/`) → `401`. `/og/api/health` returns `200` on loopback with no header, and `401` when hit externally through Apache without credentials (Apache's own auth gate fires before the app's loopback exemption is ever reached) — the documented defense-in-depth is real, not just claimed.

**API:** every state-changing route (`POST`/`PUT`/`PATCH`) across `dispatch`, `contracts`, `fleet`, `safestop`, `admin`, `scenario`, `health` (alert ack), and `retention` routers is gated by `Depends(require_operator)`; every read route by at least `require_viewer`. Two-step confirmation exists for both safe-stop (`propose`→`confirm`, 30 s window, `ConfirmationBroker`) and fleet dispatch commands (`POST /command` → `POST /command/{proposal_id}/confirm`). SQL is parameterized everywhere reviewed; the two f-string `WHERE`-clause constructions found (`contracts/pg_repo.py:141,362`) build only fixed literal fragments (never interpolate a value directly — values are always passed as `%s` params), correctly `# noqa: S608`-annotated with an honest justification. The one Jinja2 `|safe` usage (`_partials/data_table.html:19`) is only ever fed server-generated badge fragments (status/severity/age/breaker), never free-text or attacker-influenceable fields — no XSS path found. SSE endpoints (`dispatch`, etc.) require `Depends(require_viewer)` like any other read endpoint.

**Dependencies:** `pip-audit` (installed into a throwaway `/tmp` venv, deleted after use) reports **no known vulnerabilities** for either `/opt/opengrid/venv` or `/opt/ogsim/venv`. Key packages are current (`cryptography` 50.0.1, `fastapi` 0.141.1, `httpx` 0.28.1, `PyYAML` 6.0.3, `psycopg` 3.3.6) — nothing ancient or in the classic-CVE range.

**Systemd:** see F-06 — the required properties (`NoNewPrivileges`, `ProtectSystem=strict`, non-root `User=opengrid`, `MemoryMax`) are present on all ten units; only further defense-in-depth is missing, not the baseline.

**Supply chain:** `.gitignore` coverage is adequate at every checkout level found on the server (`/opt/opengrid/src` and every per-workspace `/opt/opengrid/work/<ws>`). No secrets in git history. ERCOT credentials flow through `resolve_secret`/`Secret` end-to-end with masked error paths and one-way primary→secondary subscription-key rotation on repeated 401/403 (`feeds/ercot.py::_rotate_key`); rotation is not automatic-reversible, which is appropriate (avoids flapping back to a possibly-revoked primary key mid-session).

## 4. Prioritized fix list

1. **[F-01, Critical]** Fix `ogsim.control`/`ogsim.market` to bind loopback by default:
   - `integration-sims/src/ogsim/control/cli.py:49` — change `serve_p.add_argument("--host", default="0.0.0.0")` to `default="127.0.0.1"`.
   - `integration-sims/src/ogsim/market/config.py:83` and `:117` — change the `OGSIM_MARKET_HOST` fallback from `"0.0.0.0"` to `"127.0.0.1"`.
   - Redeploy/restart `og-sim-control` and `og-sim-market`, then re-verify with `ss -ltnp` and a direct `curl http://192.168.5.35:<port>/` (expect connection refused, not `200`/`404`).
   - Add an automated check (deploy smoke test or a CI assertion) that every `og-*`/`og-sim-*` HTTP listener is bound to `127.0.0.1` before a release is considered good — this exact class of bug is otherwise silent (services start fine, health checks pass, only a LAN port scan reveals it).

2. **[F-02, Medium]** Delete `/etc/opengrid/api_keys.env.bak.20260925153256` and `/etc/opengrid/api_keys.env.bak.prequote.20260925153438` once `api_keys.env` is confirmed current; note in `deploy/README.md` that manual edits to files under `/etc/opengrid` should not leave `.bak.*` copies in place.

3. **[F-03, Medium]** Add an `Origin`/`Referer` allowlist check (matching `https://base.tocy-net.net`) to `opengrid.api.auth` for state-changing requests, or explicitly document the residual CSRF risk as accepted for MVP-S if deferred.

4. **[F-04, Low-Medium]** Scope the Mosquitto `ogtest/#` ACL pattern per-client (or move it to a dev-only ACL file not loaded in the production `mosquitto.conf`) before this deployment is treated as anything other than a test/demo environment.

5. **[F-05, Low]** Remove the `seed_hex=...` stdout print from `orchestrator/src/opengrid/safestop/keys.py::_cli` (or gate it behind an explicit flag), matching `opengrid.guardian.keys.keygen`'s existing behavior of never printing the seed.

6. **[F-06/F-07, Info]** Track as a follow-up hardening pass, not a blocker: additional `systemd` sandboxing directives (`ProtectHome=`, `PrivateDevices=`, etc.) and an explicit TLS protocol/cipher-suite policy confirmation on the host's Apache SSL module defaults.
