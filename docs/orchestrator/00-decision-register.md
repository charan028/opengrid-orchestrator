| R16 | Stops depend on the guardian | 07, 05, 02-security | **Resolved (red team RT-001/RT-002, verified; ARC-024).** An independent **Safe-Stop Authority** (`safe-stop` service, namespace `og-safestop`, ≥ 2 replicas, no dependency on `guardian`, `dispatcher`, `contracts` or `api`) holds a separate key hierarchy whose certificates carry a `safe-stop-only` extended key usage. It can sign only a scoped `SAFE_STOP`/`CEASE` (setpoint 0, V-16 ramp); hubs accept a stop signed by either the guardian or the SSA, and device rule DV-17 rejects anything else under the stop-only key. Triggers: the guardian forwards stops in normal operation; `scada-gateway` sends a restrictive utility control (block, cap, cease) that arrives while the guardian is down to the SSA, which executes it as the smallest stop scope that contains it; the out-of-band hardware-token trigger (CTL-037) is re-pointed at the SSA, so a stop works with `api`, console, `dispatcher` and `guardian` all down; an optional watchdog (off by default). **Release is never possible through the SSA.** A separate **dispatch-key epoch authority** (two-person custody, security + SRE) can advance the key epoch to invalidate a compromised guardian's outstanding commands. Also: stops are exempt from the hub's command rate limit (DV-14); the scope-stop state is retained so a reconnecting hub reads it on subscribe; fallback schedules run only while no scope stop is active and never above the last commanded export. A stop is not automatically grid-safe (it removes relief a bank or large load was receiving), so every stop follows V-16 and the affected counterparty is notified at once. Considered and not chosen: escrowed guardian-signed stops (ARC-024) — they expire during a long guardian outage and do not contain a compromised guardian. |

## D. Items outside the documentation (for the user's attention)

- **ERCOT API token reuse (live simulators):** `ercot_live.py` on the base server requests a new ERCOT login token every
  60 seconds (~1,440/day) although tokens last an hour; high failure rates have led to ERCOT suspending public API users.
  A small fix (reuse the token ~55 minutes) is ready to apply on the user's go-ahead (Q18).

  prices are read at `HB_NORTH` while the fleet settles at its load zones; the one-year ERCOT pull lacks 18 hours in May 2026.
